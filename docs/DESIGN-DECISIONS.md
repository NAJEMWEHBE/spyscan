# Spy-Detector — Design Decisions

_Captured from the `/grill-me` session, 2026-06-29. Source of truth for what we're building and why._

Goal: a tool that detects whether anyone is spying on a device. **PC (Windows) first, then any device.** Grounded in how attackers actually spy + how to detect/prevent it.

---

## Locked decisions

| # | Decision | Choice | Why |
|---|----------|--------|-----|
| 1 | **Threat model** | Everything / max paranoia — full spectrum | Local stalkerware, remote RATs/infostealers, network surveillance, rootkit/firmware/evil-maid. Widest net; we counter the false-positive cost with guardrails (see Principles). |
| 2 | **Vantage point** | On-device agent **now**, network appliance **later** (phased) | Deep OS visibility on the test PC first; network-side appliance (TinyCheck-style) added in Phase 2 for the "any device" reach (phones/IoT/TVs, zero install). |
| 3 | **Detection engine** | All three layers, day one, combined into one score | (a) Baseline-then-diff, (b) signature/IOC matching, (c) behavioral/heuristic scoring. Each is a module contributing to a single 0–100 risk score. |
| 4 | **Run mode** | On-demand deep scan → report (CLI) | Resident realtime watcher (ETW/Sysmon stream, live webcam/mic + new-persistence alerts) deferred to a later phase. |
| 5 | **Output** | Standalone **JSON + HTML report** + its own **packaged desktop app** | Verdict (clean / suspicious / likely-spied-on) + findings table (severity, evidence) + score. **CHANGED 2026-06-30 (Nino): dropped the Mission Control integration entirely — this is a separate application on its own.** JSON feeds the app UI. |
| 6 | **Stack** | **Python 3.14** | Already installed; richest security libs; becomes the portable core for the cross-device phase. |
| 7 | **Distribution** | Private now, **open-sourceable later** | Shell out to proprietary tools (Sysinternals/Defender) on the local box; keep core deps permissive (MIT/BSD) so the core can publish under MIT later with no legal cleanup. |

## Threat model — full spectrum (what we hunt)

Categories to cover (Windows Phase 1), each mapped to observable signals in the build plan:

- **Software keyloggers** (user-mode hooks `SetWindowsHookEx`, and kernel keyloggers)
- **RATs / remote-access trojans** (hidden remote control + C2 beaconing)
- **Infostealers** (RedLine/Raccoon/Lumma-class — browser cookie/session/credential theft)
- **Commercial/consumer stalkerware & "monitoring" software** (partner/employer/parental)
- **Screen / clipboard capture**
- **Webcam / microphone hijacking**
- **Abused legit remote tools** (RDP, VNC, TeamViewer, AnyDesk, ScreenConnect, Chrome Remote Desktop, hVNC)
- **Network surveillance** (LAN sniffing, MITM, rogue gateway) → primarily Phase 2 appliance
- **Rootkits / malicious kernel drivers / hidden processes**
- **Hardware** (USB hardware keyloggers, malicious USB, evil-maid) → best-effort detection
- **Persistence** behind all of the above (Run keys, Scheduled Tasks, WMI subscriptions, services, startup, DLL hijack, browser extensions)

> Exact technique → signal → data-source/API mapping comes from the research brief (`GROUNDING-BRIEF.md`, generated by the research crew) and lands in `BUILD-PLAN.md`.

## Architecture (phased)

- **Phase 1 — Windows on-device agent (MVP).** Python CLI. Collectors gather state → three detection engines → unified score → JSON + HTML report.
- **Phase 2 — Network-side appliance.** TinyCheck-style gateway (this PC or a Pi) inspects traffic from any device behind it. Reaches phones/IoT/TVs with no install.
- **Phase 3 — Cross-device / mobile.** MVT-style (Amnesty Mobile Verification Toolkit) backup/forensic analysis for Android/iOS; reuse the Python core + threat-intel/IOC layer.
- **Phase 4 — Realtime watcher + in-app live dashboard.** Resident daemon for live high-signal events; results surfaced in the standalone app (NOT Mission Control).

### Engine modules (Phase 1)
1. **Baseline-diff** — snapshot clean state (processes, autoruns, drivers, services, listening ports, connections); flag NEW/changed on later scans. Lowest FP — learns *your* normal.
2. **Signature / IOC** — YARA file rules + threat-intel feeds (domains/IPs/hashes, e.g. abuse.ch) + known stalkerware/remote-tool fingerprints.
3. **Behavioral / heuristic** — per-process / per-connection red-flag scoring (unsigned, runs from AppData/Temp, hidden window, beaconing periodicity, holds webcam/mic, keyboard-hook installed, unusual parent).

All three feed one weighted **risk score** + a per-finding severity with evidence.

## Hard principles

- **Local-only. No telemetry. No data leaves the machine.** A spy-detector must never itself be a spy. All analysis on-box; reports written locally.
- **False-positive guardrails** (required because of max-paranoia scope): code-signature/publisher reputation checks, a user-editable allowlist, baseline-diff to suppress *your* known-normal, and clear "why flagged" evidence on every finding so you can judge.
- **Defensive only.** This detects/identifies spying on devices the user owns/controls. Not for surveilling others; on a device you don't own you may lack authorization.
- **Lean on existing tools** rather than reinvent: shell out to Sysinternals (autorunsc, sigcheck), Windows Defender (`MpCmdRun`), and use vetted libs (psutil, pywin32, wmi, scapy, yara-python).

## Advanced-threat layer (nation-state / mercenary spyware) — added 2026-06-29

**Decision 8: include an advanced-threat / surveillance-awareness layer.** Goal is *awareness that a device is targeted*, not preventing the actor. We learn nation-state / mercenary-spyware TTPs (NSO Pegasus, Cytrox Predator, Candiru, Paragon, FinFisher, APT groups) only to know **what footprints to detect** — purely defensive, consuming published indicators, never replicating offense.

**Core reframe:** you don't catch state-grade spyware by copying the attack — you catch it by the **forensic artifacts + network indicators** it leaves. This is the Amnesty / Citizen Lab methodology.

### Three detection angles → mapped to our phases
| Angle | What it does | Lands in |
|-------|--------------|----------|
| **Forensic-artifact** (Amnesty **MVT**) | Match device logs/backups against published IOCs (process names, domains, log rows). Best for mobile, esp. iOS. | Phase 3 (mobile) + Phase 1 host artifacts |
| **Network** (Kaspersky **TinyCheck**) | Watch traffic for C2 / network-injection; catches even zero-click exfil; cross-device. | Phase 2 appliance |
| **Deception** (**canary tokens** / honeyfiles) | Plant tripwire docs/creds that fire when an implant reads or exfiltrates them. Catches the *unknown* implant with **no signature** — asymmetric. | New cross-cutting capability |

### Honest limits (state them in the report)
- Live on-device detection of zero-click iOS implants (Pegasus-class) is near-impossible; realistic path = **forensic (MVT) + network + Lockdown Mode**.
- IOC/threat-intel feeds **go stale fast** (actors rotate infra) → signatures alone are weak vs APT; that's why **baseline-diff + behavioral + deception** carry the load.
- The detector **only consumes** published IOCs — it does not reverse-engineer live 0days or replicate offensive capability.

### Where we learn it (responsible primary sources)
Citizen Lab, Amnesty Intl Security Lab (+ MVT & STIX2 IOC repo), Google TAG / Project Zero, Microsoft MSTIC, Lookout, Kaspersky GReAT, ESET, **MITRE ATT&CK** (Enterprise + Mobile), EFF (Crocodile Hunter / cell-site-simulator detection, SnoopSnitch, SeaGlass), Access Now, Coalition Against Stalkerware. Machine-consumable feeds: Amnesty investigations GitHub (STIX2), abuse.ch (ThreatFox/URLhaus), MISP/STIX-TAXII, YARA + Sigma rule repos.
